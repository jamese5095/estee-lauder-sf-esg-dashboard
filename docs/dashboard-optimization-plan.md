# SF × Estée Lauder ESG 看板优化方案

**版本：** Data Observation & Carbon Insight Agent Demo  
**日期：** 2026-09-14  
**项目阶段：** 客户反馈后的第二阶段方案

## 1. 项目背景

第一版看板已经向客户展示。客户当前最关注的价值，并不是由系统直接给出可承诺的减碳执行方案，而是把碳排放看板作为观察自身仓储与运输业务的窗口：通过排放量、业务量和碳强度的同步变化，识别业务作业效率、运输结构和排放集中度的变化。

因此，下一阶段将产品重心由“优化方案展示”调整为“数据观测、原因理解与机会信号识别”。现有铁路替代和 30T 柴油车集约化案例可以保留为历史验证资产，但不再作为主页面的核心叙事。

## 2. 产品定位

### 2.1 新定位

> **A carbon-based logistics operations observatory.**  
> 以碳排为核心指标，观察雅诗兰黛仓储与运输业务的运行状态。

看板需要回答四个问题：

1. 当前产生了多少碳排？
2. 排放发生在哪个仓库、线路、城市或运输方式？
3. 排放变化主要伴随哪些业务指标变化？
4. 哪些异常或集中现象值得进一步调查？

### 2.2 当前阶段不承诺的能力

- 不由系统自动决定铁路、车型或线路替换方案。
- 不在缺少成本、时效、容量和 SLA 数据时承诺方案可落地。
- 不把情景模拟减排量表述为已实现的减排结果。
- 暂不建设仓内大屏专用页面和现场设备接口。
- 暂不追求秒级实时更新，优先建立稳定、可解释的数据刷新链路。

## 3. 总体设计原则

### 3.1 数据优先

页面优先展示真实业务事实，再提供解释和信号。任何数字都必须能够追溯到明确的数据范围、时间、单位和计算口径。

### 3.2 排放必须与业务量配对

绝对排放不能单独用于评价效率。关键页面应同时展示：

- Actual emissions：实际排放量
- Shipment volume：运单量或件量
- Shipment weight：货物重量
- Transport work：吨公里
- Carbon intensity：单位业务活动碳强度

看板需要帮助客户区分：排放上升是由业务增长造成，还是单位作业效率发生变化。

### 3.3 事实、计算与情景分离

所有指标使用统一标签：

| 标签 | 定义 | 使用方式 |
| --- | --- | --- |
| Actual | 来源系统已记录的实际值 | 作为业务事实展示 |
| Calculated | 由活动数据与排放因子计算的结果 | 展示公式、因子版本与口径 |
| Scenario | 在明确假设下推演的结果 | 不作为实施承诺 |

### 3.4 Signal 不等于 Recommendation

Agent 或页面可以指出高排放集中、强度异常或结构变化，但不能直接把相关性表述为因果关系，也不能在缺少运营条件时生成确定性执行建议。

## 4. 建议信息架构

### 4.1 Home / Executive Overview

**目标：** 用一屏回答总体排放和业务运行是否发生明显变化。

建议内容：

- 总排放、运输排放、仓库排放
- 运单量、重量、吨公里
- 单票、单吨或吨公里碳强度
- 三座仓库排放汇总
- 数据更新时间和覆盖范围
- 本周期相对于基准期的变化

首页不直接给出行动方案，只提供进入运输、仓库和原因分析页面的入口。

### 4.2 Transport Footprint

**目标：** 观察运输排放与业务活动的时间和结构变化。

建议内容：

- 月度与日度实际排放趋势
- 排放与运单量、重量、吨公里的并列趋势
- 运输方式排放与运输工作量占比
- 城市、OD 线路和产品维度的排名
- Road、Rail、Air、Electric 等运输结构变化
- 可点击月份、仓库、城市和运输方式进行联动筛选

当前 2026 年 1—7 月月度数据和上海—北京明细可作为这一页面的数据基础。

### 4.3 Warehouse Footprint

**目标：** 比较三座雅诗兰黛仓库的碳排放和作业效率。

每座仓库建议展示：

- 当期排放量及占三仓总量比例
- 入库量、出库量、订单量和货物重量
- kgCO₂e / order
- kgCO₂e / tonne handled
- 电力、燃气、燃油、制冷剂等排放来源
- 日度或月度排放与作业量趋势
- 相对于自身历史基准和其他仓库的强度差异

推荐采用“三仓对比卡 + 趋势图 + 排放来源堆积图”的结构，避免将过多设备明细直接放在主视图。

### 4.4 Drivers / Variance Analysis

**目标：** 解释排放变化伴随哪些业务因素变化。

建议分析维度：

- 仓库贡献变化
- 运输方式结构变化
- 长短途运输占比变化
- 货量、重量和平均运输距离变化
- 单位作业碳强度变化
- 高排放线路或车型集中度

建议使用“变化事实 + 主要贡献维度”的表达，不把统计关联直接写成确定性原因。

### 4.5 Carbon Insight Agent

现有 `Optimization` 页面建议改为 **Carbon Insight Agent**，导航名称可使用 **Insights**。

Agent 的核心功能：

1. 解释当前页面和筛选条件下的数据。
2. 对比不同时期、仓库、线路和运输方式。
3. 识别异常、排放集中和强度波动信号。
4. 告诉使用者还需要补充哪些数据才能验证原因或评估方案。

#### 页面布局

- **顶部 Context Bar：** 时间、仓库、线路、运输方式、数据更新时间。
- **左侧或中央 Chat：** 对话、快捷问题和历史上下文。
- **右侧 Evidence Panel：** 支撑回答的指标、图表、单位、来源和数据版本。

#### 建议快捷问题

- Why did emissions change this month?
- Which warehouse has the highest carbon intensity?
- Which transport mode contributes most to the footprint?
- Which activity pool deserves further investigation?
- What additional data is required before evaluating an action?

#### 标准回答结构

**What the data shows**  
仅陈述看板可验证的事实和对比结果。

**Signal to investigate**  
指出值得进一步调查的业务维度，不直接承诺执行方案。

例如：

> **What the data shows**  
> May recorded 309.76 tCO₂e and the highest Jan–Jul shipment volume. Its carbon intensity was elevated, but remained below June.
>
> **Signal to investigate**  
> Review whether the May increase was primarily volume-led, then compare its warehouse, lane and mode mix with lower-intensity months.

#### Agent 约束

- 只能使用看板结构化数据和已批准的方法定义回答数值问题。
- 每个数字必须带有时间、范围、单位和数据类型。
- 数据不足时必须明确说明当前数据不支持可靠结论。
- 不生成未经验证的成本、时效、容量或减排承诺。
- 不将 Scenario 数值描述为 Actual。
- 不在公开页面暴露运单号、月结卡号或其他敏感字段。
- 保留问题、回答、筛选条件和数据版本记录，支持复核。

### 4.6 Methodology & Data Quality

**目标：** 让客户了解每个指标如何产生，以及数据是否完整、可复核。

建议保留：

- 核算边界和组织边界
- WTW、TTW、碳强度、吨公里等定义
- GHG Protocol、ISO 14083、GLEC 与排放因子来源
- Actual、Calculated、Scenario 的区分
- 数据更新时间、覆盖率和因子版本
- 仓库、顺丰运输和第三方运输的数据血缘

## 5. 机会信号设计

第一阶段建议使用可解释规则生成 Signal，再由 Agent 转换为自然语言。

| Signal | 判断逻辑示例 | 页面表达 |
| --- | --- | --- |
| 绝对排放异常 | 当前排放显著高于历史基准 | Emissions are above the recent baseline |
| 强度异常 | 业务量变化有限，但单位碳排明显上升 | Carbon intensity requires investigation |
| 结构性集中 | 某方式排放占比显著高于活动占比 | Emissions are concentrated in this activity pool |
| 仓库差异 | 相似作业量下仓库强度差异明显 | Warehouse intensity differs from peers |
| 线路集中 | 少数线路贡献较高排放 | A small number of lanes drive a large share |
| 数据质量 | 数据缺失、重复或更新延迟 | Data quality requires attention |

Signal 应回答“哪里值得看”，而不是未经验证地回答“应该怎么改”。

## 6. 三座仓库数据需求

建议先取得日级数据；无法取得时可从月级数据开始。

| 数据类别 | 最低字段 |
| --- | --- |
| 基础信息 | 日期、仓库 ID、仓库名称、地址、面积 |
| 业务活动 | 入库订单、出库订单、处理件数、处理重量 |
| 电力 | 用电量、计量周期、表计或账单来源 |
| 燃料 | 燃料类型、消耗量、单位 |
| 制冷剂 | 类型、补充或泄漏量（如纳入边界） |
| 可再生能源 | 光伏发电、绿电采购及凭证信息 |
| 数据治理 | 来源系统、更新时间、修订状态、责任方 |

仓库排放的基本计算逻辑为：

`Warehouse emissions = Σ(Activity data × Applicable emission factor)`

任何仓库横向比较都应同时使用业务活动分母，不能只比较绝对排放量。

## 7. 第三方运输数据的后续纳入

第三方运输可以累积进入总碳排，但必须与顺丰数据采用一致的最小审计要求：

- 唯一运单或运输段标识
- 起点、终点、距离、重量、运输方式、车型和能源类型
- 活动数据来源、供应商、时间戳和原始文件留存
- 排放因子来源和版本
- 数据覆盖率、缺失值和修订记录
- 与顺丰运输段的去重和边界核对
- Reported、Calculated、Estimated 数据状态

在完成月度对账和重复运输段检查前，第三方排放不应直接与顺丰排放合并为客户总量。

## 8. 成本信息的处理原则

客户提出未来改进建议必须包含成本预估。因此，Agent 在当前阶段只能识别机会信号；一旦进入方案评估，必须同时取得：

- 当前运输或作业成本
- 替代方案报价
- 接驳、装卸和中转费用
- 一次性系统或设备投入
- 时效变化和 SLA 风险
- 运力容量及装载率

未来方案卡片至少应同时展示：

- Estimated CO₂e reduction
- One-off cost
- Recurring cost delta
- Cost per tCO₂e reduced
- Service impact
- Confidence level

缺少以上数据时，Agent 只提示所需输入，不生成成本数字。

## 9. 数据刷新路线

当前项目优先实现可控的数据刷新，而不是承诺所有来源即时更新。

### 阶段 1：稳定导入

- 以日级或月级文件更新为主。
- 建立统一字段、去重规则和数据校验。
- 页面明确展示 `Last updated`。

### 阶段 2：计划任务更新

- 运输、WMS 和能源数据通过接口或定时文件自动同步。
- 根据数据源能力实现小时级或日级更新。
- 增加迟到数据、修订数据和异常任务提醒。

### 阶段 3：近实时服务

- 在业务价值和数据基础得到验证后，再建设事件接口和增量计算。
- 不同来源允许不同延迟，不用“伪实时”掩盖第三方数据更新限制。

## 10. 实施阶段建议

### Phase 1：数据口径与页面重构

- 确认运输、仓库和第三方运输边界。
- 建立指标字典和统一单位。
- 调整 Overview、Footprint 和 Drivers 的信息结构。
- 将 Optimization 改造为 Carbon Insight Agent 页面原型。

### Phase 2：三仓数据接入

- 接入三座仓库的业务量和能耗数据。
- 建立仓库总量、强度和趋势视图。
- 验证跨仓比较的可解释性。

### Phase 3：Agent MVP

- 接入统一指标查询层。
- 实现快捷问题、证据卡片和 Signal 规则。
- 增加回答边界、数据版本与审计记录。

### Phase 4：第三方与自动更新

- 选择一家第三方承运商试点。
- 验证数据标准、对账和审计证据包。
- 建立计划任务或接口刷新机制。

## 11. Demo 验收标准

- 所有展示数据均有明确时间、边界、单位和来源。
- 三座仓库可以独立查看并进行同口径比较。
- 排放趋势与业务量、重量或吨公里可以同步观察。
- 页面可以从总览下钻至仓库、城市、线路或运输方式。
- Agent 的每个数值回答都能在 Evidence Panel 中复核。
- Agent 能区分事实、计算和情景，并在数据不足时拒绝下结论。
- Signal 不被表述为已批准或可承诺的执行方案。
- 第三方数据在完成去重和审计校验后才能进入合并总量。
- 页面保持全英文、雅诗兰黛视觉风格和桌面端响应式体验。

## 12. 本阶段交付重点

下一版 Demo 的优先级为：

1. 三座仓库数据与运输数据的统一呈现。
2. 排放、业务量和碳强度的联动分析。
3. 可解释的异常与集中度 Signal。
4. 由真实看板数据驱动的 Carbon Insight Agent。
5. 方法、边界和数据质量的可审计表达。

最终目标不是让系统替客户承担运营决策，而是让客户更快理解业务事实、发现值得调查的变化，并明确形成可靠结论还需要哪些数据。
